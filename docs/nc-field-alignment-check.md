# NC 风场、浪场空间对齐排查

检查日期：2026-10-16。范围：/nc-wind-range、/nc-wave-range。

## 已确认的偏移与修正

原代码将 d3-contour 的输出坐标直接映射为：

    lng = west + x * dx
    lat = north - y * dy

但 d3-contour 中，第 i 列、第 j 行的样本中心在 (i + 0.5, j + 0.5)；NC 的 lo1/la1 则已是第一个样本的经纬度。

应先扣除半格：

    lng = west + (x - 0.5) * dx
    lat = north - (y - 0.5) * dy

本项目 dx=dy=0.075°，原等值面向东、向南各偏移 0.0375°。正确修复方向为向西、向北各 0.0375°，不是整度平移。

经度、纬度独立线性梯度测试在修复前均失败，修复后均通过。真实首帧风场 3137 个顶点、浪场 2867 个顶点的修复前后差值也符合该偏移；对照时关闭几何平滑，避免混入轮廓形变。

默认启用修正，页面可取消“修正等值面半格偏移”来重现旧算法。共用转换函数的其他调用方也使用正确的格点中心映射。

## 原始 NC 与 PNG 对照

从本地被 Git 忽略的 nc-灰度图/ 读取 wind_rec_2026100912.nc 和 wave_uv_rec_2026100912.nc，与 public 下两套各 120 帧切片逐帧比较：

- 原始经度 105～121.5°E，纬度 15～25.5°N，尺寸 221×141；与页面 header 一致。
- NC 纬度为南到北升序，PNG 经 flipud 转为北到南；两套全部 240 帧的有效/缺测掩膜逐像元差异为 0。
- 浪场全部帧 U/V 与预期 round 编码一致，最大量化误差约 0.025 m。
- 风场 U/V 存在约 0.25 m/s 内的量化误差，部分与当前脚本的 round 方式不同；这是数值量化差异，不是经纬度位移。

以上确认的是当前前端与交付 NC 坐标的一致性，不等于证明模型自身海陆掩膜与底图岸线完全重合；NC 内未提供额外的岸线精度保证。

## 页面如何对照

1. 打开“原始颜色面场（网格插值对照）”，它直接使用当前帧 speed/Hs 标量记录，以 L.ScalarTileLayer 双线性插值着色，不经过等值面和平滑处理。
2. 独立切换“等值面矢量场”；同时显示时，颜色面场在 pane 340、等值面在 pane 350。
3. 把等值面平滑设为 0，关闭“显示等值面填充”并打开“显示面边界线”，查看原始色斑与等值面边界。
4. 反复切换半格修正开关，查看修复前后的位置变化。
5. 浪场默认的透明海洋底图会在 pane 500 用陆地覆盖数据；排查原始掩膜时，切换到普通天地图底图或关闭图包，避免把遮挡当成坐标一致。

颜色面场使用业务色阶做连续渐变，而等值面是离散分级；其颜色无需完全相同。颜色面场在插值邻点缺测时保持透明，等值面则会追踪并平滑有效区域边界，因此沿海边缘仍可能存在局部形状差异。平滑不是坐标校正：它会收缩或改变局部轮廓，也可能改变孔洞边界。

原有标量图层将 Math.abs(null) 变为 0，会把陆地画成最低色阶，已修正为保留 null。有效波高 0 仍保留为有效数据。

## 陆地缺测点仍出现箭头

点击位置 114.1363°E、22.6254°N 在风场首帧的四个插值邻点中有三个 U/V 均为 null，仅西南邻点有效（U=-2.25、V=1）。原箭头层直接做四角插值，JavaScript 将 null 参与乘法或加法当成 0，因而在缺测区域生成非零矢量；点击弹窗却按最近邻缺测返回陆地。这是缺测过滤不一致，与等值面的半格坐标偏移是两个问题。

箭头层两种采样模式现均要求四角 U/V 全部是有限数字，风杆继承相同规则。真实有效的 0 分量不受影响。风、浪两页点击取值也不再用 0 填补缺测角：最近邻缺测仍显示无海面数据；最近邻有效但其他邻点缺测时，提示“邻近网格含缺测值，无法插值”，避免将整个混合单元都称为陆地。

浏览器在深圳附近同一缩放 10 视口检查首帧：修复前有 129 个非零箭头的采样中心被原点击规则判为无数据；修复后为 0。两页第 0、60、119 帧，以及风场拖动、缩放、原网格采样和风杆均通过一致性检查。检查针对符号采样中心；符号本身有像素长度，海上有效点的箭头图形仍可能伸过底图岸线。底图岸线与 0.075° 模型海陆掩膜的精度差异也仍存在。

另外为 Canvas 的延迟移动回调增加移除状态检查，避免快速关闭符号图层后访问空地图。

## 风、浪粒子缺测检查

两个粒子引擎原来都将缺测格点构造成 [null, null]，而插值只检查这个数组是否为空。因此缺测分量仍以 0 进入插值，混合单元会生成非零粒子速度。现统一要求 U/V 都是有限数字，否则整个格点返回 null，四角任一缺测便不插值；有效的零分量继续保留。浪粒子的方向/周期输入也执行有限值检查。

另外修复了两类沿岸问题：2px 速度缓存不能作为海陆掩膜，现按粒子实际经纬度检查四角有效性；移动路径按不超过 1px 步长检查，遇缺测立即结束当前粒子。浪粒子每帧清除旧目标，防止到达缺测处后沿用前一帧目标反向画线；垂直于运动方向的波峰短线也检查整段是否有效。检查依据仍是数据掩膜，不代表模型岸线与高精度底图完全重合。

新增 104 项确定性回归，覆盖两个真实引擎的网格插值、U/V 任一分量的 null/undefined/NaN/Infinity、有效 0、缓存边界、轨迹跨缺测条带、浪粒子旧目标及波峰短线。浏览器捕获实际 Canvas 绘制线段，风、浪第 0、60、119 帧均未发现检查点落入缺测网格；两页拖动和缩放后结果一致，纯陆地视野新绘制线段为 0，验证期间无新增页面异常。

## 风杆图形与页面风级

当前 VectorBarbLayer 使用节制风速符号：风速乘 1.94384 换算为节，按最近 5 节取整，再拆为 50 节三角旗、10 节长羽、5 节短羽。页面色阶/点击风级则按原始 m/s 的 8.0、10.8、13.9、17.2 阈值分组。因此羽数不等于风级，也不能将同一个风级固定绑定到唯一风杆形状。

实际 Canvas 绘制示例：6m/s（页面≤4级）为 1 长羽；10m/s（5级）为 2 长羽；12m/s（6级）为 2 长 1 短；15m/s（7级）为 3 长羽；19m/s（≥8级）为 3 长 1 短。7.9m/s 与 8.0m/s 分属不同页面风级，但按 5 节取整后都是 15 节，符号相同是量化结果。

独立回归提取真实 _drawBarb 方法并统计 Canvas 的长羽、短羽、三角旗，81 项检查覆盖 5～200 节、取整边界、页面风级阈值、缺测分量及跨风级同形符号；浏览器复核上述五组示例。未改动现有节制符号算法，仅在 Tab1 风杆开关下增加单位、取整和示例说明。
